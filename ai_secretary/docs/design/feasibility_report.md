# feasibility_report.md — 기술 가능성 1차 판정 (문서 검토 기준, 실기기 미검증)

모든 판정은 안드로이드의 공개된 동작 방식을 기준으로 내렸다. 실제 갤럭시에서는 아직 시험하지 않았다. → 전부 [미검증]

| 기능 | 1차 판정 | 근거 | 위험 | 확인 시험 |
|---|---|---|---|---|
| 카톡 알림 수집 | 가능 | NotificationListenerService로 다른 앱의 알림 제목·본문·MessagingStyle 메시지를 읽을 수 있음 | PC 카톡 사용 중 폰 알림이 꺼지면 수집 불가. 긴 글 잘림, 사진은 "사진" 표기만 받음. 방 알림을 꺼 두면 수집 불가 | T01~T05 |
| 카톡 전체 원문 확보 | 불가 | 공식 API 없음. 카톡 내부 DB 접근·루팅은 지침 R(6-1)로 금지 | 누락 메시지 존재 가능 → R17 명시 | — |
| 일반 SMS / 장문 SMS | 가능 | SMS_RECEIVED 방송 수신(RECEIVE_SMS 권한). 분할 문자 결합 가능 | 직접 설치 앱이라 플레이스토어 정책 제한 없음 | T06 |
| MMS | 부분 가능 | 수신 알림 + 메시지 저장소 조회(READ_SMS) | 기종별 차이 | T07 |
| RCS(채팅+) | 불확실 | RCS용 공개 API 없음. 알림 수집으로만 우회할 수 있음 | 원문 완전성 낮음 | T07 |
| 통화 녹음 파일 | 가능성 높음 | 갤럭시 녹음 파일은 공유 저장공간에 생성됨 → MediaStore(READ_MEDIA_AUDIO) 또는 SAF 폴더 지정으로 읽기 | 기종·버전별 경로 차이, 저장 완료 시점 판단 | T08~T10 |
| 통화 기록 대조 | 가능 | READ_CALL_LOG 권한으로 번호·시각·길이·방향 조회 | 권한 허용 필요 | T09 |
| 백그라운드 유지 | 조건부 | 알림 수집 서비스는 시스템이 연결 유지. 재전송은 WorkManager로 처리 | 삼성 '절전 앱' 지정 시 중단. 강제 종료 후에는 사용자가 앱을 다시 열어야 할 수 있음 | T11~T14 |
| 폰 ↔ 노트북 보안 연결 | 가능 | Tailscale은 Android와 Windows를 지원 | 회사망 정책, 노트북 꺼짐 시간 | T15~T17 |
| 통화 음성인식 | 가능 | Faster-Whisper(노트북) 또는 외부 API | 노트북 GPU 없으면 처리 느림(사양 미확인). 외부 API는 음성이 회사 밖으로 나감 | 3단계 비교 시험 |
| AI 분류·추출 | 가능 | Claude API로 JSON 구조 응답 받고 규칙으로 재검증 | 국외 이전 관련 법 검토 필요 | 4단계 |
| 앱 푸시 보고 | 가능 | 본부 → 앱 알림. 같은 망 안이면 FCM 없이도 가능 | 노트북 꺼지면 보고 중단 | 6단계 |
| 카카오 '나에게 보내기' | 가능 | Kakao Developers 메시지 API(talk_message 동의) | 폰에 알림이 실제로 울리는지 미확인. 토큰 갱신 필요 | 6단계 |
| 지정 단체방 자동 보고 | 보류 | 공식 API 없음. PC 카톡 화면 자동 조작만 가능 | 계정 제한 위험 미확인 → 지침 14장에 따라 기본 제외 | — |
| 픽셀사무실 연동 | 준비 가능 | 비서 쪽 API와 이벤트 창구는 독립적으로 구현 가능 | 픽셀사무실 구조 미확인 | 7단계 모의 시험 |

## 결론
- 1~5단계(수집, 전송, 음성인식, 분석, 장부)는 기술적으로 가능할 것으로 판단한다(실기기 미검증).
- 가장 큰 불확실 요소는 두 가지다. ① PC 카톡 사용 중 폰 알림 수집(T01) ② 녹음 파일 접근(T08). 이 둘을 0단계 시험 앱으로 먼저 확인한다.
- 사용자가 원래 요청한 '지정 단체방 자동 보고'는 V1.0에서 완료로 표시하지 않는다(지침 25장).
