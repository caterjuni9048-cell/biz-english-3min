# 0_환경검증.md — 외부 설계 검증 요청 (0단계)

너는 독립적인 시니어 안드로이드·서버·업무 자동화 검증 엔지니어다.
첨부한 설계서를 비판적으로 검증하라. 칭찬은 빼고 실제 문제점과 수정 방법만 보고하라.
확인하지 못한 사항은 미확인으로 표시하라. 추측을 실제 버그처럼 쓰지 마라.
특히 데이터 유실, 중복 업무, 사용자 확정값 훼손, 개인정보 유출, 잘못된 보고, 장애 복구, 이벤트 순서, 동시 실행 문제를 집중해서 검증하라.
판정은 PASS / CONDITIONAL / FAIL로 하라. 문제는 P0 / P1 / P2로 분류하고 근거와 수정 방법을 제시하라.

## 단계 목적
0단계: 환경 조사, 기술 가능성 검증 계획, 전체 설계 초안 검증. 아직 코드는 없다.

## 특히 판단을 받고 싶은 질문
Q1. source_id를 "기기ID + 종류 + 원본 식별자 해시"로 만드는 방식이 카톡 알림 갱신(같은 알림 key에 메시지가 누적되는 경우)과 '같은 내용이지만 실제로 별개인 메시지'를 함께 올바르게 구분할 수 있는가? 대안은?
Q2. 통화 녹음 파일의 저장 완료를 판단하는 기준(크기 고정 + 통화 기록 종료 시각)이 충분한가?
Q3. 수량을 '줄' 단위로 관리하는 설계(design_v1 4장)가 추가 → 취소 → 재확인 흐름에서 틀어질 가능성은?
Q4. 외부 AI 전송을 기본 OFF로 두면 사실상 분석이 멈춘다. 로컬 LLM이나 규칙만으로 1차 분류를 하는 대안이 현실적인가?
Q5. 노트북을 본부로 쓰는 구조(근무 시간에만 켜 둠)의 운영 위험과 클라우드 이전 시점 기준
Q6. 0단계 시험 항목(T01~T14)에서 빠진 것
Q7. 픽셀사무실 이벤트 설계(at-least-once + 소비자 offset + work_version)에서 빠진 것
